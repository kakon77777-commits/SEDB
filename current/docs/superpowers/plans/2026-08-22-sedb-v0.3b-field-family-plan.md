# SEDB v0.3B Semantic Field Family Kernel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build immutable, coherence-guarded field-family proposals and explicit reviewed families on top of v0.3A without canonical mutation.

**Architecture:** Add a `family.py` service that reuses deterministic v0.2B pair scoring and bounded semantic scanning. Persist proposals separately from reviews and formal families; review recomputes a proposal basis hash before any family is created.

**Tech Stack:** Python 3.11+, stdlib `sqlite3`, existing SEDB services, vanilla browser UI, pytest.

**Spec:** `docs/superpowers/specs/2026-08-22-sedb-v0.3b-field-family-design.md`

## Global Constraints

- Local-first only; do not push or modify GitHub.
- No runtime third-party dependency, embedding, LLM, or network call.
- Existing sparse cells, field IDs, aliases, lifecycle, semantic review, and utility behavior must remain compatible.
- Family confirmation never merges fields, creates aliases, or moves cells.
- All production changes use RED → GREEN TDD.
- Release source remains UTF-8 canonical text.
